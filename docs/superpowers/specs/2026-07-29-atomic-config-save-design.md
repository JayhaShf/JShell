# 配置原子保存设计

日期：2026-07-29

## 目标

修复配置通过 `fs::write` 直接截断覆盖的问题。保存过程中如果发生进程崩溃、写入失败或替换失败，磁盘上的上一份完整配置不得被半写文件破坏。

## 方案比较

1. **同目录临时文件加原子替换（采用）**：使用 `tempfile::NamedTempFile`，写入、刷新并同步后调用 `persist` 覆盖目标。该库在 Unix 使用重命名语义，在 Windows 使用支持覆盖的系统移动 API，平台代码较少。
2. **自行实现平台替换 API**：Unix 使用 `rename`，Windows 直接调用 `MoveFileExW` 或 `ReplaceFileW`。控制更细，但需要维护路径编码、共享模式和错误清理等平台细节。
3. **备份后直接覆盖**：实现简单，但原文件仍会先被截断，崩溃窗口没有消失，因此不满足原子保存目标。

## 写入流程

1. 验证目标配置路径存在父目录。
2. 在目标文件同一目录创建随机命名临时文件，确保替换不会跨文件系统。
3. Unix 下将临时文件权限设为 `0600`。
4. 使用 `write_all` 写入完整的版本 2 加密信封，然后执行 `flush` 和 `sync_all`。
5. 使用 `NamedTempFile::persist` 原子覆盖目标文件；替换失败时临时文件由 RAII 清理，旧目标文件保持不变。
6. 对替换后的文件再次执行 `sync_all`；Unix 下再打开并同步父目录，使目录项变更尽可能持久化。

`ConfigStore::save` 和 `ConfigStore::save_merged_preferences` 共用同一个私有写入函数，避免两套保存语义分叉。

## 错误处理

- 任一写入、同步或替换错误都返回包含目标路径和阶段信息的错误链。
- 错误日志不得包含加密前配置、主密钥、nonce 或远程凭据。
- 不主动删除或改名旧配置，不创建长期备份文件。
- 非持久化内存配置继续直接返回成功，不在磁盘创建任何文件。

## 测试

1. 已存在旧文件时，成功保存后目标内容完整替换。
2. 注入替换失败时，旧文件字节保持不变，错误可诊断。
3. `ConfigStore::save` 和合并偏好保存仍可写出可解密的版本 2 配置。
4. 完整测试、格式检查和全目标编译通过。
