# 本地配置凭据保护设计

日期：2026-07-29

## 目标

修复审计中的 P1/P2 问题：当前配置文件使用可公开读取的机器标识派生加密密钥，无法有效保护 SSH 密码、私钥内容、私钥口令和代理密码。

本次修改必须满足以下要求：

1. 首次启动自动完成密钥初始化，不要求用户设置或输入主密码。
2. Windows、macOS 和 Linux 使用各自的系统安全存储保护随机主密钥。
3. 已有版本 1 加密配置可以自动迁移，用户会话和偏好不得丢失。
4. 系统安全存储不可用时不得退回机器标识、固定常量或明文密钥文件。
5. 不修改 Release 工作流，不创建提交。

## 方案选择

采用 `keyring 3.6` 作为跨平台系统安全存储适配层：

- Windows：Credential Manager。
- macOS：Keychain。
- Linux：Secret Service。

首次运行时生成 32 字节密码学随机主密钥，并以二进制 secret 保存。正常情况下该过程没有应用内提示；如果系统凭据库处于锁定状态，操作系统可能要求用户解锁。

不生成包含明文主密钥的 `.gen` 文件。此类文件一旦与配置文件同时泄露，攻击者即可直接解密配置，不能满足本次审计目标。配置目录可以保留非敏感的格式版本或迁移标记，但当前实现不需要额外标记文件。

## 模块边界

新增 `src/session/config_key.rs`，只负责主密钥生命周期：

- `MasterKey` 表示固定 32 字节的配置主密钥。
- `PlatformKeyStore` 负责从系统安全存储读取现有密钥。
- 仅在首次运行或迁移旧格式时允许创建新密钥。
- 已存在版本 2 配置但安全存储中没有对应密钥时必须报错，不能生成新密钥覆盖旧配置。

`src/session/config.rs` 继续负责配置序列化、加密、迁移和保存。`ConfigStore` 在内存中持有本次进程使用的 `MasterKey`，后续保存不重复访问系统凭据库。

测试通过注入内存密钥存储执行，不读写开发机的 Credential Manager、Keychain 或 Secret Service。

## 运行逻辑与诊断

- 每次打开主窗口只加载一次配置，并将同一个 `ConfigStore` 传给窗口状态，避免重复访问系统凭据库和重复执行迁移。
- 配置加载失败时使用路径为空的非持久化内存配置启动，允许本次运行继续操作，但不允许后续保存覆盖磁盘上的原配置。
- 主窗口首次渲染时显示本地化错误通知，明确说明配置未加载且当前更改不会保存；详细原因同时写入日志。
- SFTP 编辑临时文件路径不得通过 `ConfigStore::load().unwrap()` 获取。配置不可用时退回操作系统临时目录，不能因此导致进程崩溃。
- 系统主密钥在进程内成功读取后缓存，多个连接和窗口不会反复触发系统凭据库交互。
- 日志可以记录安全存储类型、迁移版本、文件路径和错误分类，但不得输出主密钥、nonce、明文配置或任何远程凭据。

## 加密格式

新配置使用版本 2 信封：

- `format_version = 2`
- `kdf = "os-keyring"`
- `cipher = "xchacha20poly1305"`
- 每次保存生成新的 24 字节随机 nonce。
- 直接使用系统安全存储中的 32 字节随机主密钥执行 XChaCha20-Poly1305 加密。

随机主密钥已经具有足够熵，不再使用 Argon2 派生。Argon2 和机器标识读取代码仅保留给版本 1 配置的一次性兼容迁移，不能用于任何新保存操作。

## 加载与迁移

加载顺序如下：

1. 配置文件不存在：从系统安全存储读取或创建主密钥，然后加载默认配置。
2. 版本 2 配置：只读取既有系统主密钥并解密。
3. 版本 1 配置：使用旧机器标识完成一次解密；成功后读取或创建系统主密钥，并立即重写为版本 2。
4. 明文旧配置：由后续“限制明文兼容回退”任务按明确识别规则迁移，不在任意解密错误后盲目尝试。
5. 无法识别或损坏的配置：保留原文件并返回错误，不加载默认值后覆盖原文件。

系统安全存储不可访问、条目长度错误或版本 2 密钥丢失时，加载返回可诊断错误。原配置文件保持不变；应用现有的内存模式仍可启动，但不会静默覆盖磁盘配置。

## 开箱即用边界

- Windows 和 macOS 的正常用户会话无需额外操作。
- 带 GNOME Keyring、KWallet 等 Secret Service 实现的 Linux 桌面无需应用内密码。
- 没有 Secret Service 的精简 Linux 环境无法安全持久化主密钥，因此返回明确错误，不降级到 `.gen` 明文密钥。
- 系统凭据库锁定时，由操作系统负责解锁交互；应用不新增自定义密码界面。

## 测试

至少覆盖以下行为：

1. 首次运行生成并持久化一个 32 字节主密钥。
2. 已有密钥会被复用，不会在每次启动时轮换。
3. 版本 2 配置可使用正确密钥往返加解密，错误密钥被拒绝。
4. 版本 1 配置可以迁移到版本 2，迁移后不再依赖机器标识。
5. 版本 2 配置缺少系统主密钥时返回错误且不覆盖文件。
6. 系统安全存储错误不会触发 `.gen` 文件或其他弱降级。
7. 主窗口配置加载失败时进入不可持久化模式并显示通知。
8. SFTP 临时文件路径在配置加载失败时不会 panic。
9. 完整 Rust 测试、格式检查和全目标编译通过。

## 非目标

- 不增加用户主密码或恢复密钥界面。
- 不同步系统主密钥到其他设备。
- 不修改云同步载荷的用户密码加密机制。
- 不修改 Release 工作流或发布产物命名。
- 不在本任务中处理配置原子替换和 Clippy 存量问题。

1. 版本 2 配置、系统安全存储主密钥和版本 1 一次性迁移已完成。
