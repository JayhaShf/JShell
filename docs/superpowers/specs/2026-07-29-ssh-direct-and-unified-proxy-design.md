# SSH 直连与统一代理入口设计

日期：2026-07-29

## 目标

为每个 SSH 会话增加明确的强制直连模式，并把 SOCKS5、HTTP、HTTPS 合并到一个“使用代理”入口中。HTTPS 必须是真实的 TLS 加密代理连接，不允许只在界面上标记为支持。

本次修改必须满足以下要求：

1. 用户选择“直连”后，该会话无条件绕过环境变量代理和全局代理。
2. 用户选择“跟随全局”后，保持现有的环境代理优先于全局代理的行为。
3. 用户选择“使用代理”后，可以继续选择 SOCKS5、HTTP 或 HTTPS。
4. HTTPS 代理必须校验系统信任链、代理域名和证书有效性。
5. HTTPS TLS 握手或 CONNECT 隧道失败时禁止降级为 HTTP 或直连。
6. 现有会话中的 `none`、`socks5` 和 `http` 值必须继续工作，无需配置迁移。

## 非目标

- 不修改 Release 工作流、发布脚本或安装包配置。
- 不实现 PAC、代理自动发现、NTLM、Negotiate 或客户端证书认证。
- 不通过端口号或连接探测猜测代理协议。
- 不关闭 HTTPS 证书校验，也不提供忽略证书错误的开关。

## 方案选择

采用“统一入口加显式协议选择”的方案：

- 第一层：`跟随全局`、`直连`、`使用代理`。
- 第二层仅在“使用代理”时显示：`SOCKS5`、`HTTP`、`HTTPS`。
- 继续使用现有主机、端口、用户名和密码输入框。

未采用单一代理 URL 输入框，因为这会改变现有编辑流程，并需要迁移已拆分保存的代理字段。未采用端口自动识别，因为端口不能可靠表示协议，错误猜测还可能导致明文认证信息发往错误端点。

## 数据模型

继续使用 `Session.proxy_type`，扩展其持久化值：

| 值 | 语义 |
|---|---|
| 空字符串或 `none` | 跟随环境变量和全局代理 |
| `direct` | 强制直连，覆盖环境变量和全局代理 |
| `socks5` / `socks5h` | 使用 SOCKS5 代理 |
| `http` | 使用明文 HTTP CONNECT 代理 |
| `https` | 通过 TLS 连接代理后执行 HTTP CONNECT |

不新增重复的 `bypass_proxy` 字段。旧配置缺少 `proxy_type` 时仍默认成 `none`，因此继续继承全局策略。

保存 `none` 或 `direct` 会话时，清空该会话的代理主机、端口、用户名和密码，避免不再使用的凭据继续留在加密配置中。界面内临时切换模式时可以保留当前输入，只有确认保存时才清理。

## 路由规则

`resolve_proxy` 按以下顺序决策：

1. 会话值为 `direct`：立即返回直连，不读取或校验环境代理和全局代理。
2. 会话值为 SOCKS5、HTTP 或 HTTPS：校验并使用会话代理。
3. 会话值为空或 `none`：尝试环境变量代理。
4. 没有环境代理时尝试已启用的全局代理。
5. 没有任何代理时，仅在持久化配置正常可用的情况下采用默认直连。

`direct` 是用户对当前会话的明确选择，因此即使应用处于非持久化模式，也允许该会话直连。未知代理类型、空主机和无效端口均返回错误，不得静默直连。

## 统一代理界面

SSH 会话对话框对密码、密钥和 SSH Config 认证统一显示代理策略：

1. `跟随全局`
2. `直连`
3. `使用代理`

“使用代理”选中后显示协议分段控件和代理字段。读取旧会话时：

- `none` 显示为“跟随全局”。
- `direct` 显示为“直连”。
- `socks5`、`socks5h`、`http`、`https` 显示为“使用代理”，并选中对应协议。

全局代理设置保留现有启用开关，并在协议选项中增加 HTTPS。所有新增可见文字同时提供简体中文和英文翻译。

## HTTPS 代理连接

HTTPS 代理复用 HTTP CONNECT 请求和响应解析，但在发送 CONNECT 前增加 TLS 层：

1. TCP 连接到代理主机和端口。
2. 使用 `rustls-native-certs` 加载 Windows、macOS 或 Linux 的系统根证书。
3. 使用代理主机名构造 Rustls `ServerName`，对 DNS 名称或 IP 地址执行证书身份校验。
4. 使用 `tokio-rustls` 建立 TLS 连接。
5. 在 TLS 流中发送 HTTP/1.1 CONNECT 请求，包括现有 Basic 代理认证头。
6. 使用现有 `httparse` 逻辑要求真实 2xx 状态码，并保留响应头后已经到达的 SSH 握手字节。
7. 将建立好的 TLS 隧道作为 `ProxyStream` 交给 `russh`。

系统根证书加载失败或没有可用根证书时返回明确错误。HTTPS 代理不回退到 WebPKI 固定根，也不提供跳过校验的模式，以便企业自签 CA 可以通过操作系统信任库统一管理。

## 环境变量

环境代理解析增加 `https://`：

- `socks5://` 和 `socks5h://` 默认端口遵循 URL 解析结果。
- `http://` 默认端口为 80。
- `https://` 默认端口为 443。
- 未知协议继续返回错误。

变量优先级保持不变：`ALL_PROXY`、`HTTPS_PROXY`、`HTTP_PROXY`，各自的大写形式优先于小写形式。

## 错误处理与日志

- TLS 根证书、SNI、握手和证书验证错误保留分阶段上下文。
- 日志可以记录代理协议、主机、端口和用户名，但不得记录代理密码或 Basic 认证值。
- HTTP/HTTPS CONNECT 非 2xx、响应头超过 16 KiB 或响应不完整时返回错误。
- SOCKS5、HTTP 和 HTTPS 失败均禁止回退到其他协议或直连。
- 状态文本显示实际使用的 `DIRECT`、`SOCKS5`、`HTTP` 或 `HTTPS` 路径。

## 测试策略

### 路由与兼容测试

- `direct` 覆盖有效或无效的环境代理和全局代理。
- `direct` 在非持久化模式下仍被视为明确确认的直连。
- `none` 和空字符串继续继承环境代理及全局代理。
- 旧 `socks5` 和 `http` 会话继续解析为自定义代理。
- 未知类型、空主机和无效端口继续失败关闭。

### HTTPS 测试

- `https://proxy.example` 解析为 HTTPS 和默认端口 443。
- 本地 TLS 测试代理使用测试 CA 签发证书；受信任证书可以完成 TLS 和 CONNECT。
- 未受信任证书或主机名不匹配时握手失败。
- HTTPS CONNECT 非 2xx 时返回真实状态码。
- CONNECT 响应后附带的数据不会丢失。

## 验收标准

1. 当用户选择“直连”并连接 SSH 会话时，系统必须不访问任何环境代理或全局代理端点。
2. 当用户选择“使用代理”和 HTTPS 时，系统必须在系统证书校验通过后才发送 CONNECT。
3. 当 HTTPS 证书、TLS 握手或 CONNECT 失败时，系统必须终止连接且不得降级。
4. 当旧会话的代理类型为 `none`、`socks5` 或 `http` 时，系统必须保持原有语义。
5. 当用户保存“直连”或“跟随全局”会话时，系统必须移除该会话不再使用的代理凭据。
