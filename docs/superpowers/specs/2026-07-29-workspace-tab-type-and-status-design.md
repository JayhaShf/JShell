# 工作区标签类型与状态区分设计

日期：2026-07-29

## 目标

让远程文件标签与 SSH 终端标签能够被快速区分，同时让所有工作区标签以一致方式显示连接、保存或错误状态。调整只涉及标签栏的视觉表达，不改变标签创建、激活、关闭、分屏或文档保存逻辑。

## 已选方案

采用 B1“图标表示类型、左侧色带表示状态”的方案：

- 终端工作区显示终端图标。
- 远程文件工作区显示文件图标。
- 每个标签左侧都显示一条窄色带。
- 色带颜色表达当前状态，而不是固定表达标签类型。
- SSH 标签继续保留现有黑色背景；文件标签沿用主题标签背景。
- 删除现有状态圆点，避免圆点和色带重复表达同一信息。

未采用固定类型色带，因为文件图标和终端图标已经能稳定表达类型，继续用色带重复类型会失去连接、未保存和错误状态信息。未采用独立冷色文件背景，因为用户选择了更安静的色带方案。

## 标签状态颜色

### 终端工作区

- 绿色：工作区中的终端连接正常。
- 黄色：SSH 或串口正在连接、重连，尚未报告成功或失败。
- 红色：工作区中的终端已断开或连接失败。
- 中性色：标签引用的终端实例暂时不存在；不得在缺少状态数据时误显示为连接正常。

对于包含多个分屏终端的工作区，状态聚合优先级为：错误、连接中、状态不可用、正常。任一终端断开或失败时显示红色；否则任一终端仍在连接时显示黄色；否则只要有分屏标识无法解析为终端实例就显示中性色；只有所有非空分屏标识都成功解析且全部终端正常时才显示绿色。空工作区同样显示中性色。这样不会因第一个分屏正常而掩盖其他分屏断线、连接中或状态缺失。

终端自身的状态判定使用现有字段：`connected` 为 `true` 时正常；`connected` 为 `false` 且 `disconnected_reason` 有值时为错误；`connected` 为 `false` 且没有断开原因时为连接中。不得仅凭 `connected = false` 将初次连接误判为失败。

### 远程文件工作区

- 蓝色：文件已加载且没有未保存修改。
- 黄色：文件正在加载、检查、保存或重连，分页内容正在读取，或者存在未保存修改。
- 红色：加载失败、保存失败、保存冲突、连接离线或分页读取失败。

错误状态优先于处理中状态，处理中状态优先于未保存和正常状态。状态判定必须同时覆盖 `load_state`、`save_state`、`connection_state` 以及 `large_file.loading` / `large_file.error`，不能只检查加载和保存状态。

继续保留未保存圆点，使颜色不是唯一提示。圆点作为独立固定元素渲染在截断标题与关闭按钮之间，不再拼接进标题字符串；长文件名被截断时，未保存标记仍必须可见。

## 布局与外观

- 色带位于标签最左侧，宽度为 3 像素，并在上下留出少量间距。
- 标签内容顺序为：色带、类型图标、可截断标题、可选的未保存标记、关闭按钮。
- 类型图标使用现有图标库中的终端与文件图标，不绘制自定义 SVG。
- 色带和图标使用固定尺寸；标题继续使用截断。标签最小宽度由 80 像素提高到 104 像素，最大宽度保持 240 像素；标签较多时继续使用现有横向滚动，避免图标、未保存标记和关闭按钮互相挤压。
- 已激活标签继续使用现有字体加粗和活动背景。
- 已连接 SSH 的黑色背景和底部活动指示线继续保留。
- 悬停、点击、关闭按钮和横向滚动行为保持不变。

## 数据与渲染

`WorkspaceTabRenderData` 增加明确的视觉类型和状态，不再把 `connected_ssh`、`accent` 与标签种类混为同一判断：

- 视觉类型：`Terminal` 或 `RemoteDocument`。
- 状态：`Normal`、`Attention`、`Error` 或 `Unavailable`。
- SSH 黑底仍由“工作区是否包含已连接 SSH”单独决定。

渲染阶段根据主题把状态映射为颜色：

- `Normal`：终端使用 `success`，文件使用 `blue`。
- `Attention`：使用 `warning`。
- `Error`：使用 `danger`。
- `Unavailable`：使用 `muted_foreground`。

文件正常状态不得使用 `primary`，因为内置 JShell 主题的 `primary` 与活动标签背景相同。若主题的 `blue` 是低饱和度中性色，标签渲染层使用专用回退蓝 `#2f7faa`；有明确蓝色的主题（例如 VS Code Dark）继续使用自身的 `blue`。这样不会修改 `base.blue` 等全局主题槽位，也不会影响补全菜单、信息组件或其他派生颜色。状态色带不使用旧圆点的半透明效果，并在三套内置主题中实际检查 `success`、文件蓝、`warning`、`danger` 和中性色的可辨认性；如某个主题的语义色不可见，只针对色带做明暗校正，不改变主题的全局语义色。

类型图标与状态色带应由同一个标签渲染分支统一生成，不能为文件和终端复制两套完整标签结构。

## 可访问性与边界情况

- 类型同时由图标和现有背景语义表达，不只依赖颜色。
- 标签栏使用 `TabList`、标签使用 `Tab` 语义和稳定工作区 ID；当前标签进入 Tab 顺序，左右方向键、Home/End 在标签间切换，Enter/Space 激活，并保留清晰的键盘焦点。类型、聚合状态和本地化的未保存状态写入标签可访问名称；文件未保存继续由标题外的固定圆点表达，错误和冲突继续在文档工具栏显示文字状态。
- 多分屏工作区聚合连接状态，避免只读取第一个标签造成误导。
- 空标签组、部分分屏实例缺失、正在关闭的标签或状态暂不可用时使用中性色，不得假定成功。
- 窄窗口下图标、色带和关闭按钮保持可见，标题承担截断。
- 工作区引用的标签组或远程文档本身已不存在时，继续由现有 `filter_map` 跳过该失效工作区；`Unavailable` 用于仍可渲染、但内部终端状态不完整的标签。

## 非目标

- 不改变工作区或终端标签的数据持久化格式。
- 不按文件扩展名设置不同颜色或图标。
- 不改变文档编辑器、SFTP 面板或命令输入栏。
- 不新增标签固定、拖放、排序或分组功能。
- 不修改 Release 工作流和发布脚本。

## 测试与验证

1. 为终端聚合状态增加纯逻辑表驱动测试：全部连接、任一连接中、任一断开、空工作区、正常终端加缺失实例分别映射为正常、注意、错误和不可用，并验证错误优先于连接中、连接中优先于缺失状态。
2. 为文件状态优先级增加纯逻辑表驱动测试：正常、未保存、加载/检查/保存中、重连、分页加载、加载/保存失败、冲突、离线和分页失败映射正确。
3. 通过代码结构检查和 Debug 渲染检查确认标签使用终端与文件图标、旧左侧状态圆点已删除、独立未保存标记仍存在。
4. Debug 启动后打开已连接 SSH、连接中的 SSH、断开的终端、正常文件、未保存文件、离线文件和分页失败文件，检查色带和图标。
5. 在三套内置主题、窄窗口及大量标签下检查色带对比度、未保存标记、标题截断、横向滚动和关闭按钮不重叠。
6. 运行 `cargo fmt --check`、相关测试、`cargo check --all-targets` 和严格 Clippy。

## 验收标准

- 所有可见工作区标签都具有左侧状态色带。
- 文件标签与终端标签使用不同且熟悉的类型图标。
- 色带状态符合本设计的颜色语义和优先级。
- 初次连接不会显示为失败；多分屏断线、部分实例缺失、文件未保存、文件离线和分页错误不会被错误显示为正常。
- 长文件名被截断时，未保存标记仍然可见。
- 标签激活、关闭、滚动和原有 SSH 强调样式没有回归。
