# SSH 首次连接自动信任设计

日期：2026-08-01

## 背景

JShell 当前对 SSH 终端和 SFTP 使用严格的 OpenSSH `known_hosts` 校验。该策略可以阻止中间人攻击，但首次连接没有应用内确认或写入流程，因此新主机会直接失败并显示 `is not trusted`。同时，SFTP 监督器会对这类永久错误持续退避重试。

## 目标

实现与 OpenSSH `StrictHostKeyChecking=accept-new` 等价的行为：

- 真正未知的主机自动写入用户目录下的 `.ssh/known_hosts`，随后继续握手。
- 已存在且密钥完全匹配时直接连接，不重复写入。
- 同一主机和端口已有不同密钥时拒绝连接，不自动覆盖或追加冲突密钥。
- 吊销、否定匹配、证书颁发机构标记、文件损坏和权限错误继续失败关闭。
- SSH 终端与 SFTP 并发首次握手时只生成一条记录。
- 永久主机密钥错误不进入 SFTP 无限重试。

连接的显示名称不参与主机密钥身份判断。身份由规范化后的主机名或 IP 与端口组成；端口 22 使用 `host`，其他端口使用 `[host]:port`。

## 验证与导入规则

共享主机密钥模块将返回结构化结果，而不是依赖错误字符串：

- `Trusted`：存在无标记的匹配记录，允许连接。
- `Unknown`：目标没有任何有效或阻止性记录，可以自动导入。
- `Changed`：目标存在无标记记录，但公钥不同；无论算法是否相同都拒绝。
- `Revoked`：目标或当前密钥命中 `@revoked`，拒绝。
- `Excluded`：命中否定主机模式，拒绝，不能通过自动导入绕过。
- `UnsupportedMarker`：命中 `@cert-authority` 等非直接信任标记时拒绝。
- `FileError`：文件解析、读取或权限操作失败时拒绝。

缺少 `.ssh` 目录或 `known_hosts` 文件视为一个空的可信数据库，不视为损坏；首次未知主机可以创建目录和文件。已有但无法读取的文件仍视为错误。

## 并发与写入

`HostKeyVerifier` 在进程内使用一个共享互斥锁串行化“检查并追加”操作。锁内必须重新读取文件，避免 SSH 终端和 SFTP 同时判断为未知后重复写入：

1. 读取并解析当前文件。
2. 如果已匹配则返回成功。
3. 如果出现冲突或阻止性记录则返回结构化错误。
4. 仅在仍为 `Unknown` 时，以追加模式写入一行 OpenSSH 公钥记录并刷新文件。

写入时保留现有内容，必要时先补换行。新文件在 Unix 上使用仅用户可读写的权限；Windows 使用系统默认 ACL。公钥记录不包含会话密码、用户名或私钥信息。

## SSH 与 SFTP 行为

终端 SSH 和 SFTP Handler 继续调用同一个 `HostKeyVerifier`。自动导入在身份认证之前完成，因此只有记录成功写入后才会发送密码或公钥认证请求。

主机密钥错误将使用专用错误类型。SFTP 监督器识别这类永久错误后：

- 发布一次明确状态；
- 停止自动退避重试；
- 保留显式“重新连接”能力，供用户修正 `known_hosts` 后手动重试。

普通网络中断、代理失败或临时服务器不可用仍使用现有重试策略。

## 测试策略

实施采用测试先行，覆盖：

- 文件和目录不存在时自动创建并写入。
- 已有其他主机时追加新目标且保留原内容。
- 第二次验证直接通过且不产生重复记录。
- 非 22 端口写入 `[host]:port`。
- 同一目标存在不同算法或相同算法的旧密钥时均拒绝且不修改文件。
- 哈希主机、通配符、否定模式、`@revoked` 和 `@cert-authority` 的安全行为。
- SSH 与 SFTP 并发验证同一密钥时只写入一次。
- SFTP 对永久主机密钥错误停止自动重试，对临时错误仍重试。

按用户要求，验证集中在全部实现、测试和发布说明完成后执行；不开展全项目安全或代码审计。最终验证范围为格式化、相关测试、完整测试、全目标编译检查、Clippy 和差异检查。

## 非目标

- 不提供关闭主机密钥校验的选项。
- 不自动替换或删除旧密钥。
- 不增加首次连接确认弹窗。
- 不同步或上传用户的 `known_hosts` 文件。
- 不进行与本问题无关的全项目审计或重构。
